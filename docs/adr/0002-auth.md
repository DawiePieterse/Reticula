# ADR 0002 – Authentication and roles

Date: 2026-10-03 · Status: accepted

## Decision

A. ASP.NET Core Identity with the built-in bearer token handler. No cookies, no external identity provider.
B. Two roles. `engineer` can create and change projects, manage users, and later sign off designs. `inspector` can read projects and, from Phase 1, capture inspections.
C. No self-registration. The first engineer is created from configuration on an empty user table. Other users are added by the engineer.
D. Passwords need 12 or more characters with no composition rules, following NIST SP 800-63B. Five failed attempts lock the account for 15 minutes.
E. Access tokens last 1 hour and refresh tokens 14 days. The PWA keeps tokens and the user profile in localStorage so it can start offline already signed in. A rejected refresh ends the session, but a network failure does not.
F. Project updates carry the row version (Postgres xmin). A stale version returns 409 and nothing is overwritten.

## Why

The spec names a single registered engineer and a tablet that works offline. An external identity provider adds an online dependency at sign-in for no gain at this scale.

## Consequences

- Tokens in localStorage are readable by any script on the origin. The app loads no third-party scripts, and a strict content security policy should be added before production.
- Moving to an external provider later only replaces the login and refresh endpoints. Role checks stay the same.
